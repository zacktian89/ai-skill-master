# SkillMaster Manual QA

Date: 2026-05-29

## Setup

- Start the app with `npm run tauri dev`.
- Use a temporary Codex skills directory for QA.
- Prepare one valid skill folder with `SKILL.md`.
- Prepare one invalid folder without `SKILL.md`.

## Checks

- App opens to Skills.
- First launch creates the default skill library directory and state file.
- When Codex is not detected, Skills still opens and Settings shows a non-blocking guide.
- Import rejects the invalid folder.
- Import accepts the valid skill folder.
- Default enable can be toggled.
- Settings accepts a Codex skills directory.
- Sync creates a managed link for an enabled skill.
- Disabling the skill removes the managed link.
- Replacing a managed Codex link with a normal directory does not let SkillMaster delete it.
- Re-pointing a managed Codex link to another path does not let SkillMaster delete it.
- A managed-link mismatch appears in Settings diagnostics and skill detail.
- Breaking the main state file triggers automatic `.bak` recovery.
- Breaking both main state and backup enters a rebuildable state and exposes a rebuild action in Settings.
- Existing non-managed same-name Codex folder produces a visible conflict.
- Projects can add a folder.
- Project rule labels are exactly: 跟随默认, 在此项目启用, 在此项目停用.
- Setting a project as current context changes sync according to project rules.
- Clearing the current project returns sync behavior to the global default enabled set.
- Deleting a skill requires an explicit confirmation dialog.
- Cancelling the delete dialog leaves files and state unchanged.
- Skill library migration updates skill paths and keeps the old library unused.
- Migration feedback clearly identifies the new directory, the old unused directory, and the need to re-sync Codex.
- Settings shows state file path, backup file path, skill library path, and Codex skills path.
- Settings diagnostics covers Codex offline, state recovery, managed-link mismatch, conflict summary, and skill-library missing cases.
